  summary: O `jacoco-check` do perfil `analyze` falha com 0% de cobertura em `audit-api` durante um rebuild `-am` completo, mesmo com os 2 testes ArchUnit do módulo passando — provavelmente afeta `jdempotent-api` (mesmo padrão de módulo só-anotação) e vai afetar `validation-api` quando a Story 1.9 o preencher.
  evidence: Surgiu incidentalmente durante a revisão da Story 1.6 (`archtest`), que roda `-am` e arrasta `audit-api` no rebuild. Reproduzido de forma independente: `mvn -o -pl audit-api -am -Panalyze -Ddependency-check.skip=true verify` → a execução `check` do jacoco reporta "All coverage checks have been met", mas a execução `jacoco-check` no mesmo módulo reporta "Rule violated for bundle scos-foundation-audit-api: instructions covered ratio is 0.00, but expected minimum is 0.80" e falha o build. Os testes ArchUnit (`ArchitectureTest`) rodam e passam — o problema é que reflexão/import de classes via ArchUnit não gera instructions cobertas pelo agent do JaCoCo, então um módulo 100% anotação/enum nunca bate o mínimo de 80%, mesmo com teste real cobrindo a única regra de negócio do módulo (a regra ArchUnit em si). Não é causado pela Story 1.5 nem pela 1.6 — é uma lacuna na configuração do perfil `analyze` (Story 1.4) para módulos sem lógica executável. Vale uma exclusão/threshold dedicado para módulos `*-api`/contrato no `jacoco-maven-plugin` do pom raiz. Consequência prática: bloqueia `mvn -B -Panalyze test` (o comando exato do job `security-check` do CI, ver `.github/workflows/build.yml`) antes de alcançar qualquer módulo declarado depois de `audit-api` no reactor, incluindo `archtest` (Story 1.6) — confirmado rodando esse comando literal, que falha em `audit-api`. Separadamente, `mvn -B -Panalyze test` também falha em `jdempotent` por erro de Testcontainers/Docker Compose neste sandbox de desenvolvimento (sem Docker disponível) — não confirmado se é limitação só deste ambiente ou também afeta o runner do CI real; não registrado como item de trabalho porque não há evidência de ser um bug do repositório.
